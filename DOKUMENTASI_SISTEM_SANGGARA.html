1. Ringkasan Eksekutif & Karakteristik Sistem

Sanggara Management System dirancang khusus untuk memenuhi kebutuhan bisnis spesifik dari sanggar persewaan busana yang memiliki dinamika operasional yang berbeda dengan perdagangan ritel biasa. Terdapat 5 (lima) pilar arsitektur utama yang dibangun dalam sistem ini:

Pilar Arsitektur Khusus Sanggar SBF:
  • Model Non-Stok (Unique Asset): Tiap busana/kebaya adalah barang fisik bernilai tinggi (1 item per model), tidak memiliki stok puluhan seperti barang e-commerce.
  • Siklus Ketat 3 Hari Sewa (1 Hari Pakai): Wajib Pickup H-1, Hari Pakai (1 hari saja), dan Wajib Pengembalian (Pickin) H+1.
  • Penyimpanan 2 Metode Pembayaran Berbeda: Mendukung metode pembayaran saat DP dan saat Pelunasan berbeda (misal Tunai saat DP, Transfer saat Pelunasan) tanpa menambah tabel database.
  • Otomasi Denda 10%: Denda penalti 10% dari total nilai barang sewa jika pengembalian melewati tanggal kembali (lewat dari H+1).
  • Integrasi Geografis API Ogan: Sinkronisasi online dengan server Pemerintah Kabupaten Purwakarta untuk master data 17 kecamatan dan seluruh kelurahan.

2. Fitur dan Fungsi Sistem Secara Detail

2.1 Modul Katalog Busana (No-Stock Model)

Sistem mengeliminasi kolom stok manual pada antarmuka kasir dan manajemen produk. Setiap produk diperlakukan sebagai aset satuan eksklusif:

  • stok_total = 1, stok_siap = 1 saat ada di sanggar, dan otomatis menjadi 0 saat disewa.
  • Status ketersediaan busana: tersedia, disewa, perawatan (laundry/perbaikan payet), dan nonaktif.
  • Kategori terbagi menjadi: Kostum Tari, Baju Pengantin Adat, Kebaya & Wisuda, dan Aksesoris.

2.2 Modul Pelanggan & Integrasi API Ogan Purwakarta

Sistem terintegrasi secara real-time dengan API Wilayah Ogan Pemerintah Kabupaten Purwakarta (https://api.ogan.purwakartakab.go.id):

  • Dropdown Kecamatan memuat otomatis 17 Kecamatan resmi di Kabupaten Purwakarta.
  • Dropdown Kelurahan/Desa memuat daftar desa berdasarkan kecamatan yang dipilih secara dinamis (cascading dropdown).
  • Kolom Alamat Lengkap / Jalan untuk mencatat nama jalan, RT/RW, nomor rumah, dan patokan lokasi penyewa.

2.3 Modul Kasir Persewaan & Aturan Siklus Hari Sewa

Dirancang untuk kecepatan operasional kasir sanggar:

  • Jadwal Pemakaian 1 Hari: Kasir memilih Tanggal Acara / Pemakaian (contoh: 3 Desember). Sistem langsung menetapkan jadwal resmi:
    • Tanggal Ambil (Pickup): 2 Desember (H-1).
    • Tanggal Pakai: 3 Desember (Hari-H).
    • Tanggal Kembali (Pickin): 4 Desember (H+1).
  • Opsi Pembayaran:
    • Bayar Lunas (100%): Pembayaran penuh di awal.
    • Bayar DP (Uang Muka Min 25%): Pembayaran awal 25%, sistem otomatis menghitung sisa tagihan 75% yang wajib dilunasi saat pengambilan busana.

2.4 Penyimpanan 2 Metode Pembayaran (DP & Pelunasan)

Implementasi Tanpa Tambah Tabel Database:

Sistem memanfaatkan tabel yang sudah ada yaitu booking dan pembayaran_transaksi:

  • Kolom booking.metode_bayar_dp: Menyimpan metode saat DP (contoh: TUNAI).
  • Kolom booking.metode_bayar_pelunasan: Menyimpan metode saat Pelunasan (contoh: BANK).
  • Kolom booking.metode_bayar_terakhir: Menyimpan ringkasan otomatis hasil trigger (contoh: TUNAI (DP) • BANK (Pelunasan)).
  • Tabel data-nota.html menampilkan badge pil ganda: [TUNAI (DP)] + [BANK (LUNAS)].

2.5 Modul Cetak Struk Nota Termal (Thermal Receipt)

Menghasilkan cetakan struk kasir termal resmi (80mm/58mm) dengan identitas Sanggar Bunda Febri (SBF), nomor nota faktur, rincian produk, kotak highlight hijau status pembayaran, serta pemisahan baris Metode Bayar DP dan Metode Pelunasan.

2.6 Otomasi Denda Keterlambatan 10%

Apabila pakaian belum dikembalikan melewati batas tanggal rencana pengembalian (lewat dari H+1), sistem secara otomatis menambahkan denda keterlambatan sebesar 10% dari total nilai sewa barang ke kolom denda_keterlambatan dan total_denda.

4. Alur Bisnis (Business Process Flow)

  1. Registrasi / Pemilihan Pelanggan: Kasir memilih pelanggan atau mendaftarkan pelanggan baru dengan validasi data wilayah dari API Ogan Purwakarta serta input alamat jalan/RT/RW.
  2. Pemilihan Busana: Kasir memilih busana dari katalog (status dipastikan tersedia).
  3. Penetapan Tanggal Acara: Kasir memasukkan tanggal pemakaian acara (1 hari pakai). Sistem otomatis mengunci tanggal ambil pada H-1 dan tanggal kembali pada H+1.
  4. Pembayaran Awal: Pelanggan memilih Bayar Lunas atau Bayar DP (minimal 25%). Kasir memilih instrumen pembayaran ke-1 (misal Tunai).
  5. Penerbitan Struk Nota: Nota fisik dicetak sebagai bukti pemesanan resmi.
  6. Pengambilan Busana (H-1): Pelanggan datang mengambil busana. Jika status masih DP, kasir membuka modal pelunasan, menerima pembayaran pelunasan dengan instrumen pembayaran ke-2 (misal Transfer Bank), lalu menyerahkan busana.
  7. Pemakaian Busana (Hari-H): Busana dipakai untuk acara pernikahan, tari, atau wisuda (durasi pakai 1 hari).
  8. Pengembalian Busana (H+1): Busana dikembalikan ke sanggar. Jika pengembalian melewati H+1, sistem otomatis menerapkan denda penalti 10%. Kasir memeriksa kondisi pakaian dan menyelesaikan transaksi.

6. Otomasi Database Level Engine (MySQL Triggers)

Integritas data dijamin melalui 2 trigger yang berjalan otomatis di dalam MySQL server:

  • trg_after_insert_pembayaran_transaksi: Secara otomatis memperbarui status pembayaran di tabel booking, menghitung sisa tagihan, menyimpan metode DP dan Pelunasan, serta membentuk gabungan ringkasan metode_bayar_terakhir.
  • trg_after_insert_detail_booking: Secara otomatis mengunci ketersediaan busana di tabel produk (menyetel stok_siap = 0 dan status = 'habis') saat busana masuk dalam pesanan sewa.
